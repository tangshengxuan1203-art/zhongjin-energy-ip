Methodology V1.1

AI 宣传片制作方法论

一套可复用于企业实力片、平台产品片和项目案例片的生产流程。AI 负责提效和复现，真实现场、平台录屏、项目事实与最终判断仍由人负责。

本页如何使用 先按通用流程过关，再把仁济项目放进同一套门槛。

每个阶段只回答三件事：产出什么、仁济怎么做、什么条件满足后才能进入下一步。

真实证据优先现场、人物、录屏和运行记录是主证据；动画只解释看不见的关系。
先粗剪，后包装叙事、旁白和时长未锁定前，不投入复杂地图、粒子和数据动效。
一个工程，多版输出主片、短版、横竖版与无字幕底片从同一事实源和时间线派生。
01

七阶段生产闭环

阶段门槛没有通过，就不把问题带进下一环节。这样才能避免后期用特效补策划、用重剪补口径。

01

目标冻结

先回答为什么拍、给谁看、看完做什么。

通用产出

一页项目简报：受众、用途、核心命题、时长、版本和最终审片人。

仁济应用

建议以约 3 分钟项目案例主片为母版，服务大会、汇报与客户交流。

通过门槛

正式项目名、具体院区、片尾名称排序及主片用途全部确认。

02

事实与权限冻结

把能说、能拍、能公开的范围写成清单。

通用产出

事实表、功能状态、数据口径、拍摄许可、肖像与品牌授权清单。

仁济应用

确认“已投入使用”、科室/楼宇分析、告警工单和智能分析的真实状态。

通过门槛

每条关键表述都有确认人；演示环境脱敏；不可拍区域和人员已标记。

03

脚本与分镜

旁白、画面和证据一一对应。

通用产出

旁白 V1、分段结构、镜头表、素材来源和缺口清单。

仁济应用

按“运行—痛点—共建—平台—闭环—价值—收口”组织 20 个执行镜头。

通过门槛

删掉全部特效后故事仍成立；每个主张都能找到现场或录屏证据。

04

素材采集

先按剪辑需求拍，不按“多拍一点”碰运气。

通用产出

现场全/中/近景、完整人物动作、干净录屏、环境声和当天双备份。

仁济应用

医院侧拍运行与处置；公司侧拍共建过程并录制平台完整操作路径。

通过门槛

告警到复核的动作链完整；关键界面有原始录屏；敏感信息复核通过。

05

粗剪定结构

只解决信息顺序、镜头可信度和节奏。

通用产出

临时配音、基础字幕、无复杂包装的完整时间线和缺镜清单。

仁济应用

先验证观众能否看懂平台如何从发现异常走到现场处理和结果回填。

通过门槛

事实顺序确认、旁白锁定、镜头无硬缺口；此后不再推翻影片结构。

06

包装与声音

动效解释业务，声音建立空间，不追求泛科技感。

通用产出

数据标注、流程动画、正式配音、环境声、音乐、SFX 与字幕。

仁济应用

重点包装数据汇聚和告警工单路径；旁白选择稳定、清楚的中性声线。

通过门槛

关键界面可读、音乐不压旁白、动画不虚构功能、术语和读音准确。

07

审片、交付与复盘

审事实、审表达、审技术，不混在一轮意见里。

通用产出

终版主片、多版本输出、工程包、素材与授权、字幕和版本记录。

仁济应用

从主片派生 90 秒汇报版、30 秒预告版及 9:16 短版，不重新建立事实口径。

通过门槛

事实、隐私、画面、声音、编码和授权六类清单全部通过。

02

AI 与人的职责边界

AI 不是事实来源，也不能替代院方、业务和技术团队作最终确认。

AI 适合承担

结构化、批量化、可重复的工作

  • 把项目简报拆成旁白、分镜、拍摄清单和素材缺口。
  • 比较版本差异，检查重复信息、字幕、节奏和关键帧。
  • 生成可配置的 Remotion 动效、数据标注和多版时间线。
  • 制作临时配音、音乐方向和 5—10 秒风格预演。
  • 自动抽帧、转码、检查时长、音轨、编码和文件完整性。
必须由人确认

事实、授权、判断与最终发布

  • 项目名称、平台功能、上线状态、数据口径和对外主张。
  • 医院现场、客户名称、人员肖像、Logo 与屏幕内容授权。
  • 真实操作是否符合业务流程，人物动作是否安全、可信。
  • 旁白语气、品牌表达、关键镜头取舍和最终审片结论。
  • 对外文件、发布渠道、发布时间与后续反馈处理。
03

工程化技术路线：从零到交付怎么跑通

GitHub 管版本和协作，Remotion 管确定性画面，FFmpeg 管交付检查，剪辑软件负责人工判断和最终时间线。这一章回答的不是「用什么工具」，而是「怎样在两天内跑通一次完整链路，并且以后每次都能重跑」。

03.1先立判据：什么才算「跑通」

没有判据的技术路线只是工具清单。下面三条是硬判据，缺一条就只能算「试过一次」。

重跑一致同一份提交，在任意一台装好环境的机器上，用同一条命令渲染出同一份成片。做不到就是环境漂移或随机性没关。
改一处生效改一句旁白只动一个文件，不重导分镜、不手抄时间码、不回头改三个组件。
每句可追溯片中任何一句主张、一个数字，都能指回事实源里的一个编号和确认人。

以下情况不算跑通：只在一台机器上渲染成功；每改一个字要动三处；交付靠人脑记清单；素材和成片躺在聊天记录里。跑通的最小证据是：一条命令 + 一个可复现产物 + 一份哈希清单。

03.2六节点单向数据流：每个节点只有一个真相

节点之间只允许向下游流。下游不能反向改写上游，这是整条路线能反复重跑的前提。

节点唯一真相变更方式自动校验失败即停
① 事实facts.yaml只改这个文件，改完重新 lintfacts:lint：确认人、日期、公开级别、证据编号齐全缺任一项 → 拒绝渲染
② 文案copy.ts旁白、标题、字幕只在这里改copy:lint：出现的数字必须能对上事实编号出现事实表里没有的数字 → 停
③ 时间线timeline.ts改帧数，不手抄时间码timeline:lint：总时长、转场、钉帧是否越界负帧、超时长上限 → 停
④ 镜头shots/*.tsx + design.ts每镜一个组件，品牌 token 单独一份严格模式编译 + 关键帧静帧编译报错或静帧异常 → 停
⑤ 渲染渲染命令 + props只改 props，不动组件代码ffprobe 流检查、时长核对、抽帧比对编码 / 流 / 时长异常 → 停
⑥ 交付out/ + 素材清单由打包脚本产出，不手工复制SHA256 哈希 + 交付清单核对哈希不一致 → 停

事实被院方推翻时，正确的动作是回到 facts.yaml 改完重新往下跑，而不是在剪辑软件里手改字幕了事。

03.3事实源字段契约：让「每个数字可追溯」变成可校验的规则

# facts.yaml — 对外可用的主张只能来自这里 facts: - id: F-03 claim: "东院能源管理系统已投入使用，覆盖冷站、泵房与空调机房" source: "2026-11-05 院方能源科确认纪要" confirmed_by: "院方能源科（已口头确认，待书面）" confirmed_date: 2026-11-05 public_level: internal # public | internal | not_public evidence: [shot-07, shot-12] # 真实镜头或录屏编号 on_screen: "东院 3 个子系统已上线"
规则一数字必须挂编号copy.ts 里出现的每个数字，都要在事实表里找到对应编号；片尾可放事实编号对照表。
规则二公开级别决定去向public_level 不是 public 的事实不进对外版本，只进内部汇报版。
规则三未确认即不上屏confirmed_by 与 confirmed_date 缺一即视为未确认，只能留在工作版。
规则四证据必须存在evidence 必须指向真实镜头或录屏；找不到证据的主张直接删，不靠动画「演」出来。
规则五主张与措辞分离claim 是内部原话，on_screen 是上屏措辞；两者不同步就说明口径已变，需重新确认。
规则六变更留痕任何字段改动写进 change-log.md：时间码、原因、确认人，避免同一问题反复讨论。

03.4仓库结构与素材策略

renji-energy-film/ ├─ public/ # 脱敏素材、录屏、字体、音乐、音效（不进 Git） ├─ src/ │ ├─ facts.yaml # 事实源：唯一真相 │ ├─ copy.ts # 旁白、标题、字幕、数字口径 │ ├─ timeline.ts # 帧级时间线：镜头、转场、钉帧 │ ├─ design.ts # 品牌色、字体、字号、间距 │ └─ shots/ # 每个镜头一个组件 ├─ scripts/ │ ├─ preflight.mjs # 环境自检 │ ├─ lint-facts.mjs # 事实校验 │ ├─ lint-copy.mjs # 文案与事实对账 │ ├─ qa.mjs # 交付质检 │ └─ package.mjs # 交付打包 ├─ docs/ │ ├─ brief.md # 受众、用途、版本清单 │ ├─ storyboard.md # 分镜与素材映射（同步导出 xlsx） │ └─ change-log.md # 时间码、原因、修改、确认人 ├─ out/ # 预览、母版、多版本、质检图、SRT、哈希清单 └─ material.manifest.json # 素材清单：路径 + sha256 + 授权状态

素材为什么不入 Git：医院素材体积大且含隐私。仓库只留清单和哈希，素材放受控目录，靠 material.manifest.json 对齐版本——换机器、换人接手时先验哈希再开工，而不是靠文件名猜。

03.5环境基线：G0 环境门

环境不统一，后面所有验收都不可信。下面每一项都要在开工前自检通过。

项目基线自检方式不满足时
Node.js22（自动化流水线已锁定 22）node -v先升到 22 再装依赖
Remotion4.0.484（模板已锁定）npx remotion --version按 package-lock.json 精确安装，不装「最新版」
FFmpeg需含 volumedetect、loudnorm、select 滤镜ffmpeg -version / ffprobe -version换完整版构建，缺滤镜就做不了质检
无头浏览器首次渲染自动准备先渲一张静帧需联网预热，不要留到正式渲染当天
字体随工程入库preflight 检查字体文件缺字体会导致换行与溢出，先补齐再开工
磁盘与时长3 分钟母版预留 10—20 分钟渲染渲染前看剩余空间空间不足先清 out/ 再开渲

03.6一条命令跑通：流水线与顺序

npm ci # 按 package-lock.json 精确安装依赖 npm run preflight # 环境自检：不通过立即停，不进入下一步 npm run facts:lint # 事实校验：确认人 / 日期 / 公开级别 / 证据 npm run copy:lint # 文案与事实对账：数字必须能对上编号 npm run still -- 150 # 关键帧静帧自检，快速看单帧是否成立 npm run render:preview # 低码率预览版，用于内部评审 npm run render:master # 母版渲染 npm run qa # ffprobe 流检查 + 响度 + 抽帧 + 哈希 npm run package # 打包主片 / 短版 / 无 BGM / 无字幕 / SRT / 工程包

Windows 下 JSON 形式的 props 走文件（--props=props-nobgm.json），不要用内联双引号——引号会被 shell 吃掉，跨平台最稳的就是文件。无 BGM 版与带 BGM 版必须从同一条时间线渲染，两版才对得上。

03.7六个最容易卡住的实现点

01帧是唯一单位全片按 30fps 计算；字幕时间码由同一份文案生成 SRT，不手抄、不估算。
02确定性渲染禁用 Date.now() 与 Math.random()，伪随机用固定种子。否则同一提交两次渲染不一致，验收无从谈起。
03录屏先脱敏走演示环境、1920×1080；采集后按清单遮罩姓名、工号、病人信息、内网地址与 IP。
04声音两版同源带 BGM 与无 BGM 同源渲染；响度归一到 I=-16 LUFS、TP=-1.5 dBTP；音效音量 0.2—0.6 表示重要度，以渲染产物试听为准。
05卡点先分析后分镜强节奏 BGM 先做节拍网格分析再排镜头，切点误差控制在 3 帧内；全片节拍冲击式镜头不超过 3 处，其余拍点只动元素层。
06交付前独立终检换一个人按产品目标、功能完整、视觉方向、镜头还原、分镜一致、数据安全、音频节奏、技术质量八项复核；制作者不给自己终审。

03.8失败与回滚手册

症状根因处置
渲染中途失败、内存溢出镜头过长或并发过高分段渲染后拼接，降低并发；先用静帧定位问题镜
字幕与旁白对不上时间码是估算的以旁白音频实际时长为准反推时间码，不手调
改一句文案要重导三处文案散落在组件里文案只放 copy.ts，组件从它读取
两台机器渲染结果不同版本漂移、随机数、缺字体锁 package-lock、锁字体、禁随机，比对输出哈希
院方临时推翻一个说法片子先出了改 facts.yaml → facts:lint → 只重渲受影响镜头
素材版本错乱靠文件名口头传递material.manifest.json + SHA256 校验
字幕溢出、换行难看字体没入库字体随工程走，由 preflight 拦截

03.9第一次跑通的最短路径

仁济项目建议按这五天走，每一步都有可检查的产出，不靠感觉推进。

时间动作产出判据
Day 0（2 小时）环境与工程 bootstrap：装 Node 与 FFmpeg，复制模板工程，安装依赖，渲一张静帧加一段 5 秒短片能出片的工程静帧与短片都渲得出来
Day 1（半天）接真素材：3 段平台录屏、3 个实拍镜头、1 段旁白60 秒预览预览里能看到真实界面和真人
Day 2（半天）锁内容：填 20 条事实，写 copy.ts 与 timeline.ts，定粗剪结构通过校验的粗剪版删掉特效故事仍然成立
Day 3（1 天）精剪与声音：动效、字幕、配音、音效、卡点带 BGM 版与无 BGM 版关键界面读得清，旁白不被打断
Day 4（半天）多版本与质检：90 秒、30 秒、9:16、无字幕底片、SRT通过质检的多版本哈希与交付清单一致
Day 5（半天）独立终检与打包交付包八项复核有记录，交付清单齐全

03.10授权与合规：不能跳过的一项

工具Remotion 许可个人与小团队免费，公司可能需要付费。商业项目对外发布前先确认授权，这是最可能卡住上线的一项。
素材医院授权拆开签拍摄授权、人物肖像、屏幕内容三者分开签；原始素材不进 Git，只进受控目录。
资产字体与音乐音效确认商用授权，把授权说明随交付包一起归档，避免上线后被追责。
生成AI 画面标注明确标注为示意画面，不与实拍证据混用，也不用于佐证任何数字。
数据演示环境脱敏平台录屏一律走演示环境，生产账号不直接上镜，截图前先过一遍敏感字段清单。
存档可复现即免责事实、授权、哈希与变更记录齐全，片子出问题能定位到具体环节和责任人。

可直接复用的现成资产：120+ 张镜头配方卡（开场、界面入场、数据、字体、节奏、转场、运镜、特效、交互、收场等分类）、一支已验收的完整宣传片模板、149 个可商用音效与 BGM 备选，以及一条 30—60 秒功能片的能量弧模板（品牌开场 → 单主角立传 → 功能爬升 → 峰值收场），可作为仁济 90 秒版的骨架，先填空再挑卡。

video-shotcraft提供镜头配方、实拍与界面结合方式以及可复用组件思路。
Remotion集中管理时间线、文案和动效，适合确定性重渲与多版本输出。
FFmpeg负责转码、抽帧、响度处理、音视频流检查和交付质检。
04

仁济项目如何按这套方法开工

目前最重要的不是继续做包装，而是一次性锁定事实、权限、演示环境与素材采集。

建议的三分钟叙事

从医院持续运行进入，用一条闭环证明平台价值

0:00–0:45医院运行与管理挑战：能源保障、人工巡检、分散记录和多系统切换。
0:45–1:08院方与技术团队共同梳理业务、设备和数据关系。
1:08–1:40真实录屏展示总览、筛选、趋势和异常发现。
1:40–2:34告警、派单、现场处置、结果回填和分析参考形成闭环。
2:34–3:00回到院方实际使用和稳定运行，以项目价值与双方品牌收口。
开拍前六项确认

六项齐备后再进入拍摄和粗剪

  • 正式项目名称、具体院区与片尾双方名称排序。
  • 平台已上线功能及“已投入使用”的适用范围。
  • 医院可进入区域、出镜人员和不可拍内容。
  • 演示账号、脱敏数据和一条稳定的完整操作路径。
  • 可公开的项目画面、客户标识和数据口径。
  • 唯一终审人、集中反馈方式和每轮截止时间。
两天采集

第 1 天医院，第 2 天公司与录屏

  • 医院：外景、公共空间、机房设备、巡检、控制中心和异常处置完整动作。
  • 公司：会议、白板、研发测试、平台高清录屏和缺失镜头补录。
  • 最低标准：每个关键动作至少两个角度；录屏保持 1920×1080、无通知、无敏感信息。
同源交付

先做好主片，再派生其他版本

  • 约 3 分钟 16:9 主片，带字幕、旁白、BGM 与必要音效。
  • 90 秒汇报版、30 秒预告版及重新排版的 9:16 短版。
  • 无 BGM 版、无字幕底片、旁白干声、SRT 字幕和工程素材包。
第一个 48 小时

内容与工程两条线同时开跑

  • 第 1 小时：装 Node 22 与 FFmpeg，复制模板工程，安装依赖，渲出一张静帧——先证明环境通。
  • 第 2 小时：把 20 条待确认事实写成 facts.yaml 草稿，明确标出哪几条还没有确认人。
  • 第 1 天上午：录 3 段平台界面与 1 段真实巡检动作，脱敏后登记进 material.manifest.json。
  • 第 1 天下午：写 copy.ts 与 timeline.ts，先出一条 60 秒预览，不做包装。
  • 第 2 天上午：facts:lint 与 copy:lint 全绿，把未确认事实从对外版本里拿掉。
  • 第 2 天下午：把预览给院方看，只问事实口径与授权，不问特效。
工程侧三个检查点

每一步都留下可核验的痕迹

  • 事实检查点：每条上屏主张都能指回一个事实编号，对应 03.3 的六条规则。
  • 画面检查点：每个镜头都有 evidence，关键界面在成片里读得清，对应 03.7 的实现点。
  • 交付检查点：哈希清单、授权清单、变更记录三项齐全，对应 03.8 的回滚手册。
  • 一句话标准：任何人接手，都能在半小时内跑出同一条预览。

05

五道验收门槛

每轮只审一种问题。反馈必须带时间码、事实来源、修改原因和确认人。G0 是机器判，G1—G4 是人判。

门槛本轮只确认什么不在本轮处理通过标准
G0 环境与事实源门工具链版本、素材授权、事实源结构与校验是否全绿。任何叙事、镜头与动效。一条命令能出预览；facts:lint 与 copy:lint 零错误。
G1 脚本门受众、核心命题、事实、旁白与镜头证据。字体、粒子、复杂调色和正式配音。每个主张可核验，事实与授权清单齐备。
G2 粗剪门结构、时长、镜头真实性、信息顺序和素材缺口。最终音效、复杂动效和品牌细节。静音也能看懂，删掉特效故事仍成立。
G3 精剪门节奏、录屏可读性、字幕、调色、旁白和包装。新增主张和结构性重写。关键界面停留充分，声音清楚，动画不虚构。
G4 发布门事实、隐私、授权、Logo、编码、响度和版本归档。偏好性的大改和新创意。交付清单、工程、素材、授权与哈希完整。

仁济项目下一步：开一次启动会，同时用两小时把工程跑起来。

会议只解决六项开拍条件；工程侧同步完成环境自检并渲出一张静帧。两条线并行，第二天就能看到真实素材组成的 60 秒预览，而不是继续做新特效。
